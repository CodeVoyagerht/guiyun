# 归云 · 分类法与配置

这份只讲两件事：**东西最后落在哪**、**`guiyun.toml` 每个字段管什么**。
落位规则本身与本地归藏**完全同一套**（省/市折叠、周六→周五周期、单值层折叠、机型层多才分），
判定细节看 `references/evidence.md`。

## 一、落位形状

```
<library_root>/
├─ 区域/
│  └─ [<省>/]              ← 折叠层：只有一个省就不出现
│     └─ [<市>/]           ← 折叠层：只有一个市就不出现
│        └─ <地点>/
│           ├─ [<园区区域>/]  ← places.toml 里配了 areas 才有这一层
│           │  └─ <年>/
│           │     └─ <周期>/          ← 2024-05-18_05-24（周六 → 周五）
│           │        └─ <拍摄类型>/
│           │           ├─ [<机型>/]  ← 折叠层：同处同期真的 ≥2 台机器才有
│           │           │  └─ <搬的单位>
├─ 活动/
│  └─ <活动>/
│     └─ [<届次段>/]        ← 2024-第39届；只认出年份时不重复写年
│        └─ <年>/<周期>/<拍摄类型>/[<机型>/]<搬的单位>
├─ 抖音/                    ← 抖音拍摄类自成一枝
│  └─ <年>/<周期>/<拍摄类型>/[<机型>/]<搬的单位>
└─ <pending_dir>/           ← 默认 待定；判不准的进这里，不瞎归
   └─ <年>/<周期>/<拍摄类型>/<搬的单位>     ← 日期不明时是「未知时间」
```

`library_root` 默认 `/摄影库`。它和 `pending_dir` 都在配置里，改了就按新的来（**不会自动搬已经搬好的东西**，
要搬得自己调回去，或者把索引清掉重新 `scan` + `plan`）。

`pending_dir` 只换**树根上那个待定桶**的名字。抖音枝里还有一层叫「待定」的，那是
**拍摄类型没把握**时用的层（`抖音/年/周期/待定/`），不是同一个东西，不会跟着改名。

`<年>/<周期>` 由 `[layout] time` 决定：

| `[layout] time` | 时间层形状 | 适合 |
|---|---|---|
| `week`（默认） | `2024/2024-05-18_05-24` | 天天现行规矩：先分年，再分备份周期 |
| `day` | `2024/2024-05-18` | 一天一个文件夹，细到天 |
| `month` | `2024/2024-05` | 一天拍不了几张、或者目录太碎 |
| `year` | `2024` | 只要「哪一年」 |

**「只认出年份」永远落 `年/`**，不编周期：路径段截成 `2019`。别把它改成 `2019-01-01`，
那是编造出来的日子，看着精确、实际上没人知道是 1 月 1 号。

**「日期不可信」写成 `未知时间`。** 待定路径里的日期段是用户看得见的字面量，不要在这里放
`2025-03-01`（那只是文件被上传的日子）。

**没有可信日期时，去哪一枝？** 分两种情况，别一刀切：

| 判出来的枝 | 缺日期时落哪 | 为什么 |
|---|---|---|
| 区域 | `待定/<未知时间>/<拍摄类型>/` | 区域枝靠时间当索引键，没日期就没法定位 |
| 活动 | `活动/<活动>/<届次段>/<未知时间>/<拍摄类型>/` | 届次才是这堆素材的索引键，进待定等于把「菊花节」这个信息扔了 |
| 抖音 | `抖音/<未知时间>/<拍摄类型>/` | 同理，抖音枝本身就是分类 |

这几种在 `plan` 里仍然标成**待定**（不会自动 `apply` 出去），只是「先放在最像的地方、标出来」。

**周期固定周六 → 周五**，跨年那一周整段留在起始年：`2024-12-28 → 2025-01-03` 落在
`2024/2024-12-28_2025-01-03`，不会被劈成两个年文件夹。

### 落位的单位是什么

两种，别混：

- **整堆目录**：一个**没有子目录**、里面有媒体文件的文件夹。整堆 `mv` 走，名字原样保留
  （所以 `2024-05-18 泡泡塘 水世界/` 到了库里还叫这个名），里面的 RAW/JPG/SRT/LRF/缩略图全都跟着走。
  一次 `mv` 顶几十次，而且拍摄包的结构不会散。**同名的 `.SRT` 也靠这条一起走**。
- **散文件**：媒体文件直接躺在「还有别的子目录」的目录里（典型：网盘根的 `IMG_20240601_120000.jpg`）。
  一次一个文件。这些是最麻烦的一种，往往也是待定的主力。

一台机器上**同时满足**的文件夹优先走整堆：有子目录的文件夹不会被整堆搬，它的子目录各算各的。

### 谁算「媒体文件」

`[match] include` 决定。默认认：`jpg jpeg png heic heif tif tiff dng cr2 cr3 nef arw raf orf rw2
mp4 mov m4v avi mkv insv lrv glb` 这类。**`[match] exclude` 优先于 include**，默认排掉
`srt lrf thm lrv txt ini db xmp aae` —— 它们是素材的附属件，不该单独成为一条计划。
（`lrv` 同时出现在两边时按 exclude 算，这是故意的：预览视频不该占一条计划。）

`[match] min_size`（默认 0）能挡掉缩略图和占位文件，单位字节。真被一堆 `THM_*.jpg` 烦到就设成 `1024`。

**被 exclude 的文件不会丢。** 它们只是不触发计划；如果它们躺在要整堆搬的目录里，照样跟着走。

## 二、`guiyun.toml` 全字段

配置文件在 `~/.guiyun/guiyun.toml`（`GUIYUN_HOME` 改家目录，`--home` 临时改）。
`guiyun init` 生成一份带注释的骨架；`guiyun config` 原样打印。

```toml
[backend]
kind = "baidu"                 # baidu | local

[backend.baidu]
cli = "BaiduPCS-Go"            # 可执行文件路径；不在 PATH 就写绝对路径
config_dir = ""                # 存 BaiduPCS-Go 的登录态，空 = 用它自己的默认位置

[backend.local]
root = "E:\\网盘镜像"           # local 后端的命名空间根（下面解释）

[library]
root = "/摄影库"                # 整理进哪个目录（云端路径形状，用 /）
pending_dir = "待定"            # 判不准的落这里

[taxonomy]
source = 'D:\素材\.guicang'     # places.toml / activities.toml 在哪个目录；留空 = ~/.guiyun

[layout]
time = "week"                  # week | day | month | year
camera = true                  # 机型折叠层开不开

[scan]
roots = ["/"]                  # 从哪些目录开始扫
max_depth = 8
max_files = 200000             # 保险丝：撞上就只扫一部分，不是错误

[match]
min_size = 0
include = ["jpg", ...]
exclude = ["srt", ...]

[apply]
throttle = 0.35                # 每次网盘调用之间的间隔（秒）
retry = 2
on_conflict = "rename"         # rename | skip
```

### `backend.local.root` 是个命名空间根，不是一个盘符

local 后端里，云端形状的 `/摄影库/区域/郑州` 对应 `E:\网盘镜像\摄影库\区域\郑州` —— **相对映射**。
写 `root = "E:\\"` 才会变成你以为的那种「直接解释盘符」。理由：一份配置里只能有一个根，
否则 `/摄影库` 会有两种解释，`scan` 看到的位置和 `plan` 算出的位置对不上，同一条能搬一次错一次。

### `[taxonomy] source` 这张清单是整个工具的命门

**归云不再自己维护项目表**。地点、园区区域、活动全在归藏那两份清单里，两个工具共用一个真源：

```toml
# <source>/places.toml
[[place]]
name = "泡泡塘森林溪谷"          # 原样成为目录名
province = "河南"
city = "郑州"
lat = 34.7412
lon = 113.7210
radius_km = 3.0
aliases = ["泡泡塘", "森林溪谷"]
areas = ["水世界|水上乐园", "露营区", "花海"]   # 第一段是落进目录的名字

[[place]]
name = "开封古城"
province = "河南"
city = "开封"
aliases = ["开封"]

# <source>/activities.toml
[[activity]]
name = "开封菊花文化节"
aliases = ["菊花节", "菊展", "菊花文化节"]

[[activity]]
name = "郑州马拉松"
aliases = ["郑马"]
```

- **表头必须是 `[[place]]` / `[[activity]]`**，写错（比如 `[[places]]`）会静默读不到，全线待定。
- **别名宁多勿少。** 目录名少两个字（`泡泡塘`）就进待定，用户会以为工具坏了。
- **别放太短的通用词当别名**（`拍摄`、`素材`、`新建文件夹` 会很糟）。
- 匹配会忽略大小写和空格/下划线/间隔号：`2024-07-10 开封菊花文化节` 里的名字能命中。
- `areas` 配了却一条都对不上 → **进待定**（分不清水世界还是露营区，别硬塞）。

### 改了配置之后

| 改的是什么 | 要不要重做什么 |
|---|---|
| `places.toml` / `activities.toml`、`[layout]` | `guiyun plan` 重算即可（`plan` 零网盘调用，但**读的是索引**，索引里没有的目录照样看不见） |
| `[scan] roots / max_depth / max_files`、`[backend]*` | `guiyun scan` 重扫 |
| `[library] root` | `guiyun scan`（旧库根会被当成新的乱目录扫进来，除非它在 `skip` 里；工具永远跳过当前 `library_root`） |

`plan` 只在**索引**上工作。想让它看到网盘上刚发生的变化，只有 `guiyun scan` 一条路。

## 三、整理完之后

- **源目录会剩空壳文件夹。** 文件都搬走了，空壳还在 `未整理/` 里；`guiyun clean` 清掉。
  `clean` 只删空目录，且必须 `--yes`。
- **索引变成 `stale`。** `status` 会提醒。想接着整理下一批就 `guiyun scan`（那是几十上百次请求，不是白拿的）。
- **库根不会被再扫进来。** `scan` 永远跳过当前 `library_root`。自己写脚本时也别越过这条线，
  否则整理结果下次被自己扫一遍，越扫越乱。
- **反悔用 `guiyun undo <run_id>`。** 它只信台账，不看当前配置；先 `clean` 后 `undo` 也能还原
  （undo 会重建原位置缺的父目录）。
