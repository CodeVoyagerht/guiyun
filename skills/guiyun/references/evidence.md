# 归云 · 证据链与阈值

这份讲**凭什么**。数字来自两处：云端的文本推断在 `guiyun/rules.py` 与 `guiyun/decide.py`，
分类规则本身在 `guiyun` 借用的 `guicang/classify.py`。改代码就得同步改这里，
否则下次有人照着文档调参，调的是空气。

## 一、总原则：每样东西各自打分

一条计划要填六样东西：**分支**、**地点**、**园区区域**、**时间**、**拍摄类型**、**机型**。
前三样和后两样由归藏的规则引擎判，日期和机型由归云自己从文本里推（云端读不到 EXIF）。

```
is_auto = (归藏判定为 auto) and (日期来源不是 mtime)
```

**日期这条卡得比地点还死**：地点猜错还能靠人一眼看出（文件夹名难听但东西在），
日期猜错会把同一次拍摄拆进几十个日子，找片时全废。

## 二、日期（顺序即优先级）

| # | 证据 | 置信度 | `date_kind` | 能自动搬 |
|---|---|---|---|---|
| 1 | **文件名**里有日子 | **0.95** | `exact` | ✅ |
| 2 | **上级目录名**里有日子 | 0.95 − 0.04 × 层距（下限 **0.55**） | `exact` | ✅ |
| 3 | 目录名没日子，但**文件夹里所有带日子的文件名都指向同一天** | **0.85** | `exact` | ✅ |
| 4 | 只认到**年份** | **0.50** | `year` | ✅（落 `年/`，不编周期） |
| 5 | **只有文件修改时间** | **0.45** | `mtime` | ❌ **一律待定** |

### 认得出来的日期写法

`2024-05-18`、`2024_05_18`、`2024.5.18`、`2024/5/18`、`20240518`、`2024年5月18日`。
都要求是 20xx 年、前后不能紧贴数字（`120240518` 不算）。
`2024-05` 这种只有年月 → 补成 `2024-05-01`，置信度 0.70（比完整日子低，但比只认年份高）。
只认出 `20\d{2}` → 年份占位。

### 为什么 mtime 一律进待定

网盘上文件的修改时间**经常是上传时间**，不是拍摄时间。一次厦门之行拍了 300 张，
分三天传上去，照 mtime 分会变成 3 个「拍摄日」—— 而这个错误**事后没人看得出来**，
因为路径看起来完全正常。这是最坏的失败模式：错得静悄悄。

所以 mtime 只做两件事：给个大概的年份参考、和别人的日期打架时当反证。**永不自动搬。**

### 第 3 条（文件名共识）的两个前提

1. 目录名**没有**能用的日期（不然第 2 条就赢了）。
2. 文件夹里**所有**带日期的文件名都指向**同一天**。哪怕有一个不对，这条整体作废 ——
   半个拍摄被拆成两半，比不整理更烦人。

### 目录链的层距衰减

`0.04` 每层。从文件所在目录往上数：第 0 层 0.95、第 1 层 0.91、第 2 层 0.87…… 到 **0.55** 封顶不再降。
理由是：`/未整理/2024-05-18 泡泡塘/DJI_0001.JPG` 里的日子非常可信；
`/2024/未整理/杂七杂八/a.jpg` 里那个 `2024` 只能说"大概是这一年"，不该和文件名里的日子同分。

## 三、分支（谁先进谁赢）

| 顺序 | 命中什么 | 置信度 | 结果 |
|---|---|---|---|
| 1 | 路径含「抖音 / douyin / 竖屏」 | **0.90** | `抖音/…`，**不要求认出地点** |
| 2 | 命中 `activities.toml`（置信 ≥ **0.70**） | 0.78–0.90 | `活动/…` |
| 3 | 命中 `places.toml` | 见第四节 | `区域/…` |
| 4 | 都没有 | — | `待定/` |

**抖音是独立一枝**，判的是「这条素材是为抖音拍的吗」，不是「画面是不是竖的」——
手机竖拍的日常素材不该全进抖音枝，所以**不按画幅比例猜**。

## 四、地点与园区区域

比较前先归一化：去掉空白、`_`、`-`、`·`、`・`，全部小写。

| 证据 | 置信度 |
|---|---|
| 坐标在某个地点半径内（云端基本没有，除非文件名带经纬度） | 0.95 − 0.33 × 距离/半径（边缘 ≈0.62，进待定） |
| 路径段里出现地名（含别名） | min(0.88, 0.66 + 0.03 × 名字长度) |

**园区区域**只在 `place.areas` 里找别名，最长匹配胜出，命中给 **0.90**；
**地点配了 areas 却一条都对不上 → 进待定**。这是刻意的：分不清水世界还是露营区，就别硬塞。

**地点是 `is_auto` 的硬门槛**：认不出地点又不是活动，就是待定，不管日期多准。
宁可让用户说一句「这是泡泡塘」，也不能自己编一个地名往库里塞。

## 五、拍摄类型

云端只看名字（目录名、文件名，以及整堆搬时那堆里的文件名）。顺序即优先级：

| # | 证据 | 置信度 |
|---|---|---|
| 1 | FPV / Avata | **0.90** |
| 2 | 延时 / timelapse / hyperlapse | **0.88** |
| 3 | 航拍 / 无人机 / aerial | **0.86** |
| 4 | 地拍 / 手持 | **0.84** |
| 5 | 无人机机型：Mavic / Mini / Air / Phantom / Inspire / Matrice / Neo / `FCxxxx` | **0.84** |
| 6 | **同一堆里有同名 `.SRT`**（云端的遥测线索，见下） | **0.80** |
| 7 | 地面机型：Sony / Canon / Fuji / Lumix / ILCE / EOS / X-T / Osmo / Pocket / iPhone | **0.80** |
| 8 | 名字以 `DJI_` 开头但机型不明 | **0.55**（进待定） |
| 9 | 什么都没有 | **0.50**（进待定） |

### 第 6 条：同名 `.SRT` 是云端唯一能用的遥测证据

`DJI_0001.MP4` 旁边躺着 `DJI_0001.SRT`，说明这堆是无人机拍的——**名字对上**才算
（`_stem()` 比较，不是随便有个 SRT 就算）。而且只在三种情况下才动手：

- 当前拍摄类型置信 **< 0.80**（已经有更硬的证据就不覆盖）；
- 证据里**没有** `path:ground`（路径里明写「地拍」的，那个 SRT 多半是人塞进去的字幕）；
- 改判后**重算分支与状态**（不然抖音枝里会留一条"航拍但待定"）。

改判会往 `explain` 里留一句「同目录有同名 .SRT 遥测，按航拍算（0.80）」。

**拍摄类型不够 0.75 就进待定**（`抖音/…/待定/` 也是这个道理）——`--shot 航拍` 钉一次就够。

## 六、机型

云端**读不到 EXIF**。所以机型只认名字里明写的型号 —— 目录名、文件名、以及整堆搬时
**那堆里最多十二个文件名**（目录名常常不含机型，但里面的 `DJI_0001.JPG` 含；
漏了这条整类航拍素材都会变"没认出来"）。

| 命中 | 置信度 | 落成的名字 |
|---|---|---|
| 具体型号：Mavic 3 / Mavic 2 / Mini / Air / Phantom / Inspire / Avata / Matrice | **0.80** | `DJI Mavic 3`、`DJI Mini 4`… |
| Sony：`ILCE-7RM3`、`ILCE-6400`、`A7R…`、`A7M…` | **0.80** | `Sony ILCE`、`Sony A7` |
| Canon：`EOS R5`、`EOS R6`、`5D`、`6D`、`90D`、`850D` | **0.80** | `Canon EOS`、`Canon 5D` |
| Fuji：`X-T4`、`X-H2` | **0.80** | `Fuji X-T`、`Fuji X-H` |
| 运动相机/口袋机：Osmo、Pocket、GoPro、Insta360 | **0.80** | 对应名 |
| 只有厂牌：DJI、Canon、Sony、Nikon、Fuji、Leica | **0.62** | 厂牌 |
| 文件名以 `DJI_` 开头但型号不明 | **0.58** | `DJI` |
| 都没有 | — | 不分机型层 |

匹配不区分大小写。`_CAM_RULES` 目前 17 条正则，加新机器就往那张表里加一行（`(正则, 名字)` 元组）。

**机型不影响能不能自动搬。** 认不出就平铺在拍摄类型下面；认出来了也不一定分层 —— 见下。

## 七、机型层是折叠的

`[layout] camera = true`（默认）时，**同一个「分支 + 地点 + 园区区域 + 周期 + 拍摄类型」组里
出现 ≥2 种不同机型**，才在下面加机型层。只有一台机器的那些日子不会有那层。

理由：绝大多数拍摄只有一台机器，为了整齐给每天都套一层 `DJI/` 是纯噪音 ——
找片时多一层点击，路径变长一倍。只有真的两台机混拍（无人机 + 相机）的同期才值得分开。

`[layout] camera = false` 就永远不分层，全平铺。

## 八、人工判定（`manual.json`）

存 `~/.guiyun/manual.json`，**机器推断永远压不过人**。字段跟归藏对齐：

```json
{
  "version": 1,
  "entries": {
    "/未整理/泉州西街": {
      "place": "泉州西街",
      "area": "水世界",
      "branch": "区域",
      "shot": "地拍",
      "date": "2024-03-15",
      "date_kind": "exact",
      "camera": null,
      "set_at": "2026-11-15T21:03:12"
    }
  }
}
```

- **键是网盘路径**（云端形状，`/` 分隔），精确匹配优先；钉在上级目录上对子文件也生效（最近的祖先赢）。
- 人钉住的字段置信度记 **1.0**，并且会在 `reasons` 最前面留一条痕（`explain` 里看得见）。
- **稀疏**：只写你给过的字段。钉了地点没钉日期，日期还是机器推的。
- 钉了地点会自动按清单补齐**省/市/园区区域**——不然路径里会少一层（`开封/开封古城` 只剩地点）。
- `date_kind` 跟着日期一起存：`--date 2019` 存 `year`，`--date 2024-03-15` 存 `exact`。
  别手改成 `exact` + `2019-01-01`，那等于告诉工具"1 月 1 号拍的"。
- 钉了之后 `guiyun review --set` 会**立刻重算、重算理由，并打印那条的新结论**；`--clear` 撤掉。
- 钉住了但还缺东西（比如地点有了、拍摄类型还是 0.55）→ 仍然待定，原因会跟着变。
  **钉错了不会静默通过。**

## 九、待定的原因怎么写

`pending_why` 是给用户看的一句话，别写成日志。顺序（第一条命中的就是答案）：

| 情况 | 话 |
|---|---|
| 完全没有日期 | 没找到日期 |
| 日期只有 mtime | 只有上传时间，没有能信的拍摄日期 |
| 抖音枝但拍摄类型没底 | 抖音这条的拍摄类型只有 0.5x 的把握（可以 `--shot` 钉一次） |
| 清单缺文件 | `places.toml` / `activities.toml` 没找到，在哪找的 |
| 地点、活动都没认出来 | 路径里没出现 places.toml 或 activities.toml 里的地名/活动名 |
| 其他（置信不够、园区区域对不上） | 直接抛归藏的第一条 `note`（「拍摄类型只有 0.62 的把握」这种） |

「为什么不动」是对人说的，**不要在这里输出权重和正则**；那些用 `guiyun explain`。

## 十、调参时的红线

- **别把 `AUTO_THRESHOLD` 往下调来"多搬一点"。** 真正的代价是误搬，而误搬要用户自己找回来。
- **别让 mtime 变成可自动搬。** 哪怕用户说"我上传时间就是拍摄时间"—— 那是他的错觉，或者只对一部分成立。
  要做就让他在 `review --set` 里一条条钉。
- **别为了省事把「≥2 种机型才分层」改成"总是分层"。** 那会让绝大多数路径多一层无意义的目录。
- **别让归云自己再长出一套清单。** 地点和活动只有一个真源（`places.toml` / `activities.toml`），
  两边各认各的地名，本地和网盘就会长出两棵不一样的树。
