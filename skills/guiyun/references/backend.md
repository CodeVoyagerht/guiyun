# 归云 · 后端契约

这份讲**怎么跟网盘说话**。所有结论都来自 BaiduPCS-Go v4.0.2 的源码，不是猜的 ——
因为你没登录真机时也得能把代码写对。

## 一、为什么是 BaiduPCS-Go，不是官方 SDK

单文件、无依赖、能用 BDUSS 直接干活。官方开放平台要申请、要过审、要维护回调，为了搬几个文件夹不值得。
代价是它**没有 JSON 输出**，只能解析人类可读的表格 —— 所以下面的解析细节必须写死，不能靠感觉。

可执行文件：仓库里带了 `C:\Users\life2\Projects\guiyun\.tools\bpc\BaiduPCS-Go-v4.0.2-windows-x64\BaiduPCS-Go.exe`。
配置里 `[backend.baidu] cli` 写绝对路径最稳（PATH 里那份被 DSH 进程继承的旧 PATH 影响，容易找不到）。

## 二、三条硬契约（写代码前必须记住）

### 1. `ls` 没有 `--json`，是 tablewriter 渲染的表格

但它是**无边框、无竖线、长文件名不折行**的（`SetBorder(false)` / `SetColumnSeparator("")` /
`SetAutoWrapText(false)`），列之间只有空格。所以解析锚点只有一个：**日期列固定 25 宽**
（`YYYY-MM-DD HH:MM:SS`，固定东八区）。日期左边是 `序号 大小`，右边是文件名，**目录名带尾 `/`**。

`ls` 也**不递归**。递归得自己 BFS 一层层 `ls`。

### 2. 退出码永远是 0

所有错误都是打印后 return，进程照样成功退出。**成功与否只能看输出字面量**：
出现 `操作成功` / `创建目录成功` / `重命名成功` 才算成，出现 `失败` 或 `遇到错误` 就是没成。
把这两类都当成功、或者只看 returncode，是这类工具最常见的翻车点。

### 3. `mv` 的语义**取决于目标存不存在**

| 目标状态 | 实际行为 |
|---|---|
| 不存在 | **重命名 / 换路径**：把源搬到那个完整路径（可同时换目录+改名） |
| 存在且是目录 | **移动进去**：`to = 目录 + "/" + 原名`，**保留原文件名，不可能边移边改名** |
| 存在但不是目录 | 报「目标 X 不是一个目录, 操作失败」 |

所以工具里的 `move(src, dst)` 永远**先建 dst 的父目录、再确认 dst 自身不存在**，然后 `mv src dst`。
**不要自己拼一个"移进去"的调用** —— 目标恰好存在时，源会被静默塞进那个同名目录，
路径比你以为的多一层，而且不报错。

## 三、输出字面量速查（判成功用）

| 命令 | 成功 | 失败 |
|---|---|---|
| `mkdir` | `创建目录成功: <path>` | `创建目录 <path> 失败, <err>` |
| `mv` | `操作成功, 以下文件/目录移动成功:` 或 `重命名成功:` | `操作失败, 以下文件/目录移动失败:` / `重命名失败:` |
| `cp` | `操作成功, 以下文件/目录拷贝成功:` | `操作失败, 以下文件/目录拷贝失败:` |
| `rm` | `操作成功, 以下文件/目录已删除, 可在网盘文件回收站找回:` | `操作失败, 以下文件/目录删除失败:` |
| `quota` | `用户名: X, 总空间: A, 已用空间: B, 比率: C%` | — |
| `who` | 打印当前账号信息 | — |

错误文本模板：`{op}: 遇到错误, 远端服务器返回错误, 代码: {code}, 消息: {msg}`。
代码 `0` 表示成功。大小是 1024 进制的人类格式：`123B` / `3.45KB` / `1.20MB` / `1.00GB`，**目录显示 `-`**。

## 四、错误码 → 工具行为

后端把错误码翻译成三种异常，上层据此决定停不停：

| 类别 | 代码 / 文案 | 抛什么 | 上层的反应 |
|---|---|---|---|
| 登录态 | 31045、3、-4、-5、-6、-11、9019 | `AuthError` | 整批终止，让用户重新 `guiyun login` |
| 风控 | 132（安全验证）、112（页面已过期）、「请求过于频繁」、「稍后再试」 | `RateLimitError` | **立刻熔断整批**，报出已搬几条、被什么挡住 |
| 冲突 | 31061、-8、-30 | `BackendError` | 按 `on_conflict`（默认改名） |
| 不存在 | 31066、-3、-9 | `BackendError` | 记失败，接着下一条 |
| 其它 | — | `BackendError` | 按 `apply_retry` 重试 |

**风控是熔断不是重试。** 百度对异常调用量的反应是封号，不是限速。撞上 132 还继续冲，
等于拿用户账号赌。熔断后 `status` 会显示 `aborted`，用户可以过一会儿再 `guiyun apply --yes` 接着搬
（方案还在，已搬的那些会被重算成 `skip`，前提是**先 `scan`**）。

节流：每条 `mv` 之间 `apply.throttle`（默认 0.35 秒）。`clean` 的删除也走同一个节流。
目录列表有缓存（每次 `ls` 存一份，`mkdir`/`move`/`copy`/`delete` 成功后增量更新），
目的是把「N 次移动」从 3N 次 API 调用压到 1+N 次。

## 五、路径里的通配符陷阱

`ls`、`mv` 的路径参数会先做 shell 通配符匹配。**路径里含 `*` `?` `[` `]`** 会被当模式，
不匹配时报「未匹配到路径, 请检测通配符」，而不是"路径不存在"。
文件夹名叫 `[精选]`、`精选*` 的会踩这个坑。

绕法：这类目录交给 `local` 后端处理（或者改名），别在云端跟它硬碰。
报错文案里出现「未匹配到路径」时，先回头看看路径里有没有这几个字符，不要误判成登录失效。

## 六、登录

```bash
guiyun login            # 交互式，BDUSS 用 getpass 输入，不回显
GUIYUN_BDUSS=... guiyun login   # 脚本里用环境变量，别把 BDUSS 写在命令行上
```

登录态存在 BaiduPCS-Go 自己的配置目录（或用 `[backend.baidu] config_dir` 指定）。
`config_dir` 必须写**绝对路径**：BaiduPCS-Go 的 `GetConfigDir()` 会把相对路径拼到
**它自己 exe 所在目录**，不是当前目录（源码 `internal/pcsconfig/pcsconfig.go`），
写成相对路径会在 exe 旁边静默建一个目录，人找不到。归云会提前报错拦住。

`--bduss=...` 仍然支持，但那串会留在 shell 历史和进程列表里，等同把密码写在命令行上；
交互输入或环境变量都好过它。

`guiyun status` / 任何子命令开头的 `_ensure()` 都会跑一次 `who` 检查连通，
不通就停下来说「没登录」，**不会带着坏登录态继续跑**。注意 `who` 没登录时也退出 0，
所以判断依据是输出里的 `uid:`（0 = 没登录）和 `用户名:`，不是退出码。

**BDUSS 等同于登录态。** 不要打进日志、不要写进报告、不要在对话里复述。
用户贴给你的时候回一句"已收到，不会再显示"，然后闭嘴。

## 七、真机上第一次跑，要验证这一条

源码看 `mv` 给的是 `opera=move` + 两个完整路径，理论上"换目录+改名"能一次完成。
但**没在真网盘上验证过**（开发时用的是 local 后端）。

首次真机验证步骤：

```bash
guiyun login
guiyun status
# 造一个测试用的：
#   网盘上建 /_guiyun_test/a.bin ，再建空目录 /_guiyun_test/out
#   然后手工 mv：mv /_guiyun_test/a.bin /_guiyun_test/out/a2.bin
# 期望：out 里出现 a2.bin（换了目录也换了名），而不是报错、也不是 a.bin
```

如果真机上它**不能**一次改名换目录，退路是：先 `mv src target_dir`（原文件名移进去）再
`mv target_dir/原名 target_dir/新名`（此时目标不存在 → 走重命名）。两次调用，但语义确定。
在 `BaiduBackend.move()` 里加这个退化分支即可，其它层不用动。

## 八、local 后端（不登录也能跑整套）

```toml
[backend]
kind = "local"

[backend.local]
root = "E:\\网盘镜像"
```

`root` 是这个后端的**命名空间根**：云端形状 `/摄影库/x` ↔ `E:\网盘镜像\摄影库\x`。
写 `root = "E:\\"` 才会"直接解释盘符"。**一份配置只认一个根** —— 否则同一个 `/摄影库`
有两种解释，`scan` 看到的位置和 `plan` 算出的位置会对不上，同一条能搬一次错一次。

用途：网盘客户端把云端挂成本地盘；或者在一块测试盘上先演练一遍整套流程。`mv` 跨盘自动退化成
复制 + 删除源。

## 九、`clean` 的安全边界（别绕过）

删除是这套工具里**唯一不可逆**的动作（云端删了进回收站，本地删了进回收站，但都不是"挪一下"）。
所以语义收到了最窄：

- `Backend.delete(path, *, expect_empty=False)`。**删目录必须显式声明它是空的。**
- local 后端：目录且未声明空 → 直接抛错；声明了也用 `os.rmdir`（非空会自己报错），
  **不用 `shutil.rmtree`** —— 递归删除在整理工具里没有存在的理由。
- 云端后端：缓存里知道它是目录、又没声明空 → 抛错，不进 `rm`。
- `clean` 自己只挑「一件东西都不剩」的目录，由深到浅（子目录删完父目录才算空），
  `scan_roots` 根和 `library_root` 默认都不碰。
- 无 `--yes` 时返回码 `2`，只报数不删。

`apply` 只做 move，`undo` 只做反向 move。**这套工具里没有任何"删素材"的路径**，
